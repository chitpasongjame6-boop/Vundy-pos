# Vundy-pos

## ติดตั้ง / อัปเดตบน Linux Mint ด้วยคำสั่งเดียว

เปิด Terminal ในโฟลเดอร์ Git ของโปรเจ็กต์เดิมบน Linux แล้วรันด้วยผู้ใช้ปกติ:

```bash
bash run.sh
```

สคริปต์ตรวจโค้ดก่อน แล้วเรียก `git pull --ff-only origin main` (ปิด rebase/autostash และป้องกันการทับไฟล์ที่ ignore) → ติดตั้งเครื่องมือที่จำเป็น → `npm ci` → Build → ตรวจ schema/indexes → เปิดเว็บรุ่นใหม่ใน Docker และตรวจสุขภาพระบบ พร้อมแสดง URL ที่เปิดใช้งานได้ (ไม่ได้เปิดเบราว์เซอร์ให้อัตโนมัติ)

- สำรองข้อมูลผ่าน Settings ก่อนอัปเดต ใช้โฟลเดอร์เดิมที่ติดตั้งอยู่เพื่อคง `.env.linux.local`, MongoDB keyfile และ Docker volumes เดิม ไม่ต้องรันด้วย `sudo`
- หยุดหากมีไฟล์แก้ไข/ไฟล์ใหม่ที่ Git ยังไม่ติดตาม, อยู่สาขาอื่น, มี commit เฉพาะในเครื่อง หรือดึงโค้ดไม่สำเร็จ ไม่ stash/reset/ลบไฟล์ให้เอง และไม่ Build โค้ดเก่าเงียบ ๆ แทนการอัปเดต
- `bash run.sh --lan` / `--localhost` / `--port 3001` ยังใช้ได้ ถ้าไม่ระบุจะคงค่าเดิม
- ถ้าต้องการ Build ไฟล์เดิมโดยไม่ดึง Git ใช้ `bash run.sh --no-update` (ขั้นตอนติดตั้ง/Build อาจยังต้องใช้อินเทอร์เน็ต)
- โฟลเดอร์ที่แตกจาก ZIP ไม่มีประวัติ Git จึงอัปเดตอัตโนมัติไม่ได้ สคริปต์จะหยุดแจ้ง ไม่สร้าง repository หรือเขียนทับข้อมูลให้เอง
- เครื่องที่มี `run.sh` รุ่นเก่าต้องรับไฟล์รุ่นใหม่นี้ก่อนครั้งเดียว: `git pull --ff-only origin main && bash run.sh` หลังจากนั้นใช้เพียง `bash run.sh` ทุกครั้ง ไม่มีการตั้งเวลาอัปเดตขณะขายสินค้า
- การเรียก `bash install-linux.sh` โดยตรงยังติดตั้ง/Build เฉพาะโค้ดในเครื่อง ไม่ดึง Git

ดูรายละเอียดการตั้งค่า สำรองข้อมูล และแก้ปัญหาที่ [คู่มือ Linux](docs/setup.md)

## เพิ่มสินค้าจากบาร์โค้ดอัตโนมัติ

- ใช้บัญชีเจ้าของ เปิด **เพิ่มสินค้า** แล้วสแกนบาร์โค้ดแรกได้เลยโดยไม่ต้องคลิกช่อง ระบบจะค้นจาก Open Food Facts และฐานข้อมูลร่วม เช่น Open Beauty Facts ผ่าน API v3 (`product_type=all`)
- หรือพิมพ์บาร์โค้ดใน SKU แรกแล้วกด Enter / ปุ่ม **ຄົ້ນຫາຈາກ Barcode ທຳອິດ** รองรับบาร์โค้ดตัวเลข 8, 12, 13, 14 หลัก; SKU ภายในร้านยังใช้ได้แต่ไม่ส่งออกไปค้นภายนอกอัตโนมัติ
- ตรวจบาร์โค้ดซ้ำในร้านก่อนค้น รวมสินค้าและขนาดที่ปิดขาย หากพบจะแสดงลิงก์ไปสินค้าที่มีอยู่ ไม่สร้างสินค้าหรือเพิ่มสต็อกเอง
- เติมเฉพาะชื่อ (รวมยี่ห้อเมื่อจำเป็น), หมวดหมู่ และขนาดที่ยังว่าง/ยังไม่แก้ไข พร้อมรูปเท่าที่มี ชื่อไม่รับประกันว่าจะเป็นภาษาลาว หมวดหมู่แก้ไขหรือเลือกของร้านได้ ขนาดจากแค็ตตาล็อกคือขนาดบรรจุต้นฉบับ ไม่ใช่ขนาดน้ำหอมแบ่งขาย
- การดึงรายละเอียดใช้ **SKU แรกของสินค้านี้** ขนาดอื่นสแกนกรอก SKU ได้ตามเดิม ไม่ดึงคนละสินค้ามาทับข้อมูลหลัก
- ต้นทุนกีบ/บาท เรต ราคาขาย สต็อก และวันหมดอายุ ต้องกรอกตามสินค้าจริง ไม่ดึงหรือเดาจากฐานข้อมูลสาธารณะ ตรวจสอบก่อนกดบันทึกเสมอ
- ยกเลิกการดึงข้อมูลได้ ปุ่มยกเลิกล้างเฉพาะค่าที่เติมและยังไม่ได้แก้ไข ไม่ล้างข้อมูลที่คุณกรอกเอง หากไม่พบ/ออฟไลน์/เกินอัตราเรียก API ยังเพิ่มสินค้าเองได้ตามปกติ
- รูปนำเข้าจะถูกดาวน์โหลดเฉพาะตอนบันทึก จำกัด 5 MB ตรวจชนิด/ขนาดจริง บีบอัด WebP และใช้ R2/ทางเลือกจัดเก็บเดิมของแอป รูปที่อัปโหลดเองมีสิทธิ์เหนือรูปจากแค็ตตาล็อก หากดึงรูปไม่ได้ ให้ปิดตัวเลือกใช้รูปภายนอกแล้วบันทึกอีกครั้ง
- ระบบเก็บลิงก์แหล่งที่มา วันดึงข้อมูล และสถานะรูปไว้ใน `Product.catalogSource` แสดงเครดิตในรายละเอียดสินค้า และเก็บไปกับ Backup/CSV แบบเต็ม (CSV ราคาสินค้าแบบ 5 คอลัมน์ยังเหมือนเดิม)
- ไม่ส่งต้นทุน ราคาขาย ข้อมูลลูกค้า หรือข้อมูลธุรกิจไปยังฐานข้อมูลภายนอก ไม่สร้าง/แก้ไขสินค้าบน Open Food Facts และไม่เรียก API นี้ตอนขายหน้าร้าน

การเชื่อมต่อไม่ต้องใช้ API key หรือแพ็กเกจเสียเงิน ต้องมีอินเทอร์เน็ตตอนค้นครั้งแรก Cache อยู่ในหน่วยความจำ (พบข้อมูล 24 ชั่วโมง / ไม่พบ 10 นาที, สูงสุด 250 รหัส) รวมคำขอซ้ำ และจำกัด 15 คำขอออก/นาทีต่อ process รวม redirect; เคารพ 429 และ timeout หากรันหลาย instance ที่ใช้ IP เดียวกัน ควรเพิ่ม shared rate limiter ก่อนขยายใช้งาน ผลค้นหามีลายเซ็นจาก `SESSION_SECRET` เดิม (หรือ `OWNER_PASSWORD` ตามระบบล็อกอิน) มีอายุ 24 ชั่วโมง หมดอายุให้ค้นใหม่โดยไม่ต้องล้างข้อมูลที่กรอก

ตั้ง `PRODUCT_LOOKUP_USER_AGENT="VundyPOS/0.1 (your-contact-email@example.com)"` ใน environment ฝั่งเซิร์ฟเวอร์ได้ เพื่อระบุผู้ติดต่อจริง หากไม่ตั้งจะใช้ชื่อแอปและลิงก์โครงการ ไม่มีการเพิ่มหรือเปลี่ยนคีย์ R2 ให้ ก่อนเปิดใช้งานควรแจ้งการใช้ API ผ่านแบบฟอร์มในเอกสารผู้ให้บริการ และตรวจเงื่อนไข ODbL/Database Contents License กับ CC BY-SA สำหรับรูป โดยเฉพาะเมื่อนำข้อมูลไปเผยแพร่หรือแจกจ่ายต่อ; การให้เครดิตอย่างเดียวไม่ได้แทนข้อกำหนดอื่นของใบอนุญาต

เอกสารต้นทาง: [API และข้อจำกัด](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/), [อาหาร/เครื่องสำอางและฐานข้อมูลร่วม](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/tutorials/scanning-cosmetics-pet-food-and-other-products/), [ใบอนุญาตข้อมูลและรูป](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/tutorials/license-be-on-the-legal-side/)

## เงินกีบและเงินบาท

- ราคาขาย ยอดขาย ส่วนลด และกำไร ใช้กีบเป็นหน่วยหลัก ใบเสร็จแสดงเฉพาะกีบเสมอ
- เจ้าของตั้งเรตได้ที่ **ตั้งค่า → เงินบาท / เรต** แยกเรตรับเงินลูกค้ากับเรตซื้อสินค้า ไม่มีการดึงเรตตลาดอัตโนมัติ และไม่มีเรตตัวอย่างที่เปิดใช้เอง
- หน้าเพิ่มสินค้าเลือกต้นทุนกีบหรือบาทได้แยกแต่ละขนาด กรอกเงินบาทได้ถึงสองตำแหน่ง ระบบแปลงเป็นต้นทุนกีบที่ฝั่งเซิร์ฟเวอร์
- หน้าใบสั่งซื้อ/รับสินค้าเก็บจำนวนเงินและเรตของรอบนั้น เมื่อรับเข้าจะคำนวณต้นทุนเฉลี่ยถ่วงน้ำหนักกับสต็อกคงเหลือ (ปัดเป็นกีบเต็ม) ไม่เปลี่ยนราคาขายหรือกำไรในบิลเก่า
- ใบสั่งซื้อบันทึกต้นทุนสต็อก ไม่ได้หักเงินในลิ้นชักอัตโนมัติ หากใช้เงินจากลิ้นชักจ่ายผู้ขาย ให้บันทึกเงินออกในหน้ากะขายและเลือกสกุลเงินที่จ่ายจริง
- การขายรับบาทรองรับ **เงินสดบาทอย่างเดียวทั้งบิล** ยังไม่รองรับโอนบาทหรือผสมบาทกับกีบในบิลเดียว ต้องเปิดกะก่อนรับบาท ทอนและคืนเงินเป็นกีบตามยอดบิลเดิม
- ช่องรับเงินบนใบเสร็จของบิลบาทระบุว่าเป็นมูลค่าเทียบกีบ ไม่แสดงเงินบาท/เรต รายละเอียดบาทจริงดูได้ในประวัติบิลภายในระบบ
- กะขายนับเงินกีบและบาทแยกกัน การรับบาท/ทอนกีบ/คืนเงินจะเป็นรายการเงินเข้าออกอัตโนมัติ **ไม่ต้องบันทึกซ้ำเอง** การคืนบิลบาทต้องมีกะเปิดของผู้คืน และบันทึกในกะที่คืนจริง ไม่เปลี่ยนเงินสดในกะเก่า
- หน้าปิดยอดรายวันแยกยอดรับสุทธิจากการขาย ไม่รวมเงินเปิดกะหรือเงินเข้าออกทั่วไป กีบรับสุทธิอาจติดลบเมื่อรับบาทแล้วทอนกีบ ให้ใช้หน้ากะขายเพื่อตรวจเงินจริงในลิ้นชัก
- Export แบบเต็มและ Backup เก็บข้อมูลสกุลเงิน/เรตด้วย Backup รุ่น 2 รับไฟล์รุ่น 1 ได้ ข้อมูลเก่าที่ไม่มีสกุลเงินถือเป็นกีบ

รายละเอียดข้อมูล: LAK เก็บเป็นกีบเต็ม, THB เก็บเป็นสตางค์ (`*Minor` และช่อง `*Thb`), เรตเก็บเป็นกีบต่อบาท × 10,000 การเปลี่ยนเรตใช้เฉพาะรายการใหม่ ถ้าเรตเปลี่ยนขณะขายต้องตรวจยอดและกดบันทึกใหม่

หลังอัปเดตโค้ด ให้หยุดแอปเดิมแล้วรัน `npm run prisma:generate` และ `npm run build -- --webpack` จากนั้น `npm start` (หรือใช้ขั้นตอนอัปเดตของ `run.sh` บน Linux Mint) ฟิลด์ใหม่เป็น optional ไม่ต้องล้างหรือเขียนข้อมูลธุรกิจเก่าทับ
